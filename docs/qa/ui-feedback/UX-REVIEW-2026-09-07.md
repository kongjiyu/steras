# STERAS UI/UX review — 7 September 2026

## Scope and conclusion

Browser testing covered the live public website and MOTAC reviewer workspace at https://linkos-496505.web.app, plus an organizer draft against the local Firebase emulator. Desktop viewport: 1440 × 900; mobile viewport: 390 × 844. The organizer `NewEvent.tsx` component was verified unchanged from the deployed revision. Emulator findings are therefore relevant to that UI implementation, but are not production submission UAT.

The visual identity is coherent. The most urgent work concerns reliable saving, visible validation, and trustworthy connection status. This review adds findings and recommendations only; no new application fixes or deployment were performed in this review.

## Prioritized findings

## What works well

1. Cream, olive, and gold establish a recognizable civic identity. The main homepage action is easy to locate.
2. Upload-first preparation and optional editing match the organizer's task better than requiring duplicate manual entry. The remaining save semantics need correction.
3. Calendar empty-search recovery and registration validation give concrete explanations. Sampled public and reviewer pages fit the mobile width without horizontal overflow.

The subjective design verdict is a coherent branded interface with repetitive nested cards in the application flow. There is no basis to infer how the design was generated. Improve workflow density and state communication before adding visual decoration.

## Secondary recommendations

- **Mobile homepage:** measured height is about 9,185 pixels, versus 5,461 on desktop. Keep the main CTA and shorten mobile journey previews with compact steps or optional detail. Preserve the requested desktop staircase composition.
- **Hero readability:** the mobile paragraph overlaps a busy performers/photo region. A more solid cream backing would improve readability. This is a visual observation, not a measured contrast failure.
- **Public categories:** event cards/details expose raw values such as `religious` and `concert`, while filters use friendly labels. Reuse one display-label map.
- **Terminology:** explain Stage 2, provisional category, and hard floors in language appropriate to organizers. Standardize organizer/organiser spelling.
- **Public participation:** the page refers to registered public viewers, while registration is organizer-focused and login copy mentions organizer or authority. Explain the access route; do not silently expand account roles.
- **Reviewer empty state:** reduce the large empty priority graphic and replace poetic copy with “No applications assigned to you” plus a useful next action. Zero assigned applications was a valid state in the tested account.

### Cognitive-load checklist

For the long organizer application: three checks pass (clear overall task, recognizable section grouping, visible typographic hierarchy); five need improvement (manageable chunks, one decision at a time, fewer simultaneous choices, reduced working-memory demand, progressive disclosure). These are qualitative design checks, not measured cognitive-performance results.

### Persona impact

- **First-time organizer:** may believe Save details persisted their work and may not understand why Submit did nothing visible. Prioritize UX-01 and UX-02.
- **Mobile organizer:** repeated scrolling makes missing evidence difficult to find. Prioritize UX-04 and UX-05.
- **Agency reviewer:** a LIVE label while offline weakens confidence in the operational queue. Prioritize UX-03.

## Suggested implementation order

1. Fix persistence and validation visibility; verify refresh, navigation, failed save, and invalid submission.
2. Release the verified connection warning and make freshness indicators accurate.
3. Repair sticky completeness and add navigation/filtering for long evidence lists.
4. Simplify mobile homepage previews and standardize labels and empty-state copy.

Relevant design follow-ups: `/harden` for state and recovery, `/clarify` for labels, `/adapt` for mobile flow, `/distill` for repeated content, then `/polish` after the behavior is reliable.

## Implemented follow-up

UX-01 through UX-05 now have fixes: Save details persists before closing; offline save retains edits; errors receive focus and link to the relevant section/item; browser Online/Offline replaces the static LIVE claim; completeness sticks during scroll; progress steps navigate; and the missing-evidence filter hides completed items. Unsaved detail edits trigger the browser reload/close warning. The action area remains in normal flow to avoid covering content.

Browser retest: saved event name survived reload; offline save kept its input and edit mode; invalid submission focused the visible alert at y=155 on mobile; an evidence error focused `evidence-DOC-A02`; missing-only filtering reduced 18 items to 16 for the fixture; completeness stayed visible after scrolling on desktop and mobile. Mobile document width remained 390 pixels.

The isolated release passed typecheck, lint, build, 180 frontend tests and 334 function tests. The working tree's earlier 192 frontend tests include unrelated unpublished code, so the release count is intentionally different. The final layout adjustment was rebuilt successfully. Secondary visual/copy recommendations remain suggestions outside these five fixes.
